# Глибокий Аудит та Звіт про Проблеми Front-End Частини

Після детального аналізу фронтенд-кодової бази (Vue.js + Vite + Pinia + PrimeVue) було виявлено низку критичних архітектурних, стилістичних та UI/UX проблем, які роблять поточний стан додатку "дуже поганим". Нижче наведено детальний опис проблем та чіткі інструкції для їх вирішення (для наступного розробника).

---

## 1. Критичні Проблеми з CSS та Версткою

**Проблема:** У файлах (наприклад, `ManagementView.vue`) масово використовуються утилітарні класи на кшталт `flex`, `gap-2`, `bg-slate-50`, `w-full`, `rounded-lg`. Однак, ані **Tailwind CSS**, ані **PrimeFlex** не встановлені у `package.json` та не налаштовані. 
**Наслідок:** Всі ці класи ігноруються браузером, що призводить до абсолютно зламаної або непередбачуваної верстки.
**Рішення:** 
- Необхідно терміново встановити та налаштувати Tailwind CSS у проєкті (або PrimeFlex, хоча Tailwind є сучаснішим вибором і краще інтегрується з темою Aura).

## 2. Архітектура Компонентів (Монолітність)

**Проблема:** Файл `ManagementView.vue` перетворився на величезний моноліт (~600 рядків коду). В ньому змішана логіка управління групами, студентами, викладачами та дисциплінами через величезний блок `v-if/v-else`.
**Наслідок:** Код важко читати, тестувати та підтримувати. Будь-яка зміна може зламати інший таб.
**Рішення:** 
- Провести декомпозицію `ManagementView.vue` на окремі компоненти.
- Створити нові компоненти у папці `components/`: `ManageGroups.vue`, `ManageStudents.vue`, `ManageTeachers.vue`, `ManageDisciplines.vue`.
- Замість самописних кнопок для вкладок використати нативний компонент `Tabs` (TabList, Tab, TabPanels) від PrimeVue.

## 3. Неправильне або неповне використання PrimeVue

**Проблема:** Хоча PrimeVue встановлено, його потенціал використовується лише частково. В коді спостерігається "мікс" нативних HTML-елементів та PrimeVue:
- Використовуються нативні чекбокси `<input type="checkbox">` замість компонента `<Checkbox>`.
- Використовуються стандартні HTML `<form>` замість структурованих PrimeVue форм (Form, FloatLabel тощо).
- `JournalView.vue` використовує звичайний `<InputText type="number">` для оцінок.
**Рішення:**
- Повністю перевести всі елементи управління на PrimeVue (використати `Checkbox` для вибору дисциплін).
- В журналі замінити `InputText` на `<InputNumber :min="0" :max="100" />` для захисту від вводу некоректних даних на стороні клієнта.

## 4. UI/UX та Дизайн (Відсутність Естетики)

**Проблема:** Дизайн виглядає застарілим, базовим і не "преміальним". 
- Симулятор ролей в шапці (`App.vue`) займає занадто багато місця у вигляді ряду кнопок, що робить шапку перевантаженою на мобільних пристроях.
- В `shared.css` жорстко задано `.page-container { max-width: 900px; }`. Це обмежує таблиці і змушує їх виглядати стиснуто на великих моніторах.
- Редагування елементів в таблицях відбувається "inline" (прямо в рядку через зміну стану на інпути), що викликає "стрибання" висоти рядків таблиці.
**Рішення:**
- **Шапка:** Замінити ряд кнопок симулятора ролей на один гарний випадаючий список (`Select` або `Dropdown`).
- **Стилі:** Прибрати обмеження в 900px для контейнерів, дозволити адаптивний гумовий дизайн (використати 100% ширини з невеликими відступами). Оновити кольорову палітру на більш сучасну, додати тіні та плавні переходи (hover/transition).
- **Редагування:** Відмовитися від inline-редагування в таблицях. Натомість використовувати спливаюче вікно (`Dialog`) від PrimeVue при натисканні кнопки "Редагувати".

## 5. Роутинг та Структура Навігації

**Проблема:** Сайдбар (`aside.sidebar`) у `App.vue` побудований на звичайних посиланнях (`router-link`). 
**Рішення:** 
- Використати компонент меню від PrimeVue (наприклад, `Menu` або `PanelMenu`), який надасть вбудовану доступність (a11y), клавіатурну навігацію та набагато кращий візуальний вигляд.

---
**Висновок для наступного виконавця:**
Проєкт потребує термінового рефакторингу фронтенду. Почніть з ініціалізації Tailwind CSS, потім декомпозуйте `ManagementView.vue` і повністю перейдіть на екосистему PrimeVue для всіх форм і модальних вікон. Дизайн повинен бути кардинально покращений, щоб стати сучасним і динамічним.
